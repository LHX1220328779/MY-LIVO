## 根因和实际修改

问题出在地图产品的回波选择，而非原始雷达驱动丢失回波。粗网格只有少量近处扫描线，也会压制同格中覆盖其他地面位置的远处扫描；原补点要求近处点足够拟合平面且候选贴合该平面，未通过就留下矩形缺口。坡面、真实起伏及秩不足的小块尤其容易受影响。

地面细分补点现在先选平面 3 cm 内最近的原始观测；某个 5 cm 子列没有这种候选或平面无法拟合时，选该子列最近的原始观测。只有原来未覆盖的子列才能补点，不插值、不更改任何点坐标。平面系数保持 double，使候选和落盘使用同一判据。高处灯柱/墙面的距离优先、看穿规则及植被规则保留。

取消导出时整帧删除停车扫描，让距离、覆盖与实际写出的扫描集合一致；分块体素过滤仍正常去重。强度图变大是恢复真实观测的代价。历史全程存档重导出由 83,365,195 点增至 99,005,176 点（约 +18.8%，binary XYZI 约 1.33→1.58 GB）。

性能修改：只为 LIVO 保留 VIO 确实需要的点/协方差列表，移除同一帧的中间重复复制；复用体素估计与点云转换缓冲区容量；标准 launch 默认使用 `OMP_WAIT_POLICY=PASSIVE`，避免工作线程在帧间忙等。显式设置的环境变量仍优先。没有通过减点、缩地图、降迭代次数或停用估计约束换取速度。

新增 `reexport_intensity` 工具直接调用生产 `exportIntensityMap`，读取既有扫描、标定和最终校正，输出到新的目录，可修复旧强度产品而不重跑估计。RGB 导出独立。

## 复现

```bash
cmake --build build/fast_livo --target fastlivo_mapping reexport_intensity -j2
# NEW_OUTPUT 必须不存在；源存档和校正均只读。
OMP_NUM_THREADS=8 OMP_WAIT_POLICY=PASSIVE build/fast_livo/reexport_intensity SOURCE_FUSION NEW_OUTPUT
bash scripts/run_wuhu_round.sh ROUND --mode lio \
  --dataset /home/project/data/haibo/xingye/13/20261027/ros2bag \
  --calibration config/carlibration/xingye/truck13/v014_camphoto/calibration.json --rate 2
```

查看完整地图应使用整图或所有时间分块的并集。单个 `map_N.pcd` 只代表部分时间，距离优先可能选择了其他时间分块中的更近观测。标准地图选择 `--source all`；仅关键帧产品本来就会减少覆盖。
