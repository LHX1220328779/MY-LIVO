## 1. 指标退化核查

现象（10-19 提交文档的待查项）：5–20 m 地面“非关键帧跨扫描平面偏移 >5 cm”比例，10-14 旧版 `wuhu_29_lio_8` 4.5 %，10-15 之后的轮次 10–13 %，集中在装载停车段。

根因：`scripts/evaluate_wuhu_lio.py` 的 `compare_map` 对每个 b 扫描，从时间间隔 ≥5 s 的较早候选里只取车距最接近 30 m 的一个 a。车停着时 b 的位置不变，约 300 个停车段 b 扫描于是全部和同一个进场扫描比较；候选是“每 10 个非关键帧取 1”，关键帧位置不同，候选集合就不同。所以这个比例主要由“碰巧选中哪一个进场扫描”决定。

| 同一张地图，只改候选相位 0 / 3 / 5 / 7 | >5 cm 比例 |
| --- | --- |
| 旧地图 `wuhu_29_lio_8` | 4.54 / 6.31 / 7.87 / 12.21 % |
| 新地图 `mcp8_lio_full` | 11.70 / 10.09 / 13.59 / 4.89 % |

修正：b 扫描的 a 在 20–40 m 内的所有较早候选中轮换（`within[pair_count % len(within)]`），停车段 b 约对应 28–30 个不同的 a。修正后相位 0 / 5：旧 15.00 / 15.21 %，新 15.83 / 17.59 %；优化后偏移中位旧 18.8 / 19.4 mm，新 20.1 / 21.0 mm（原生 23.7 / 24.2 vs 23.4 / 24.6 mm）。剩下约 1.5 mm 的差在同一指标的相位波动范围内，没有继续追。

独立检查（不依赖这个采样方式），旧 = 新：
- 进场 → 停车窗口 ICP 残差：原生相同，优化后相近；
- 停车段逐扫描地面抖动：偏移标准差 0.32 vs 0.34 cm，倾角中位 0.013 vs 0.018°；
- 进场扫描（171–176 s）对停车地面：噪声范围内一致。

结论：这是评估采样问题，不是建图退化，评估脚本已修正。以后不要拿修正前的该项数字跨轮次比较。

## 2. 效率

基线 `mcp8_lio_full`（362c75b 之前的同配置 LIO 全程轮次，未开 RViz）：回放 879 s，收尾 167 s（回环 66.4 s + 最终求解约 3 s + 地图块导出 89.5 s），评估 204 s（参考导出 56 s 后才开始轨迹评估 140 s），标准地图导出 78 s 与评估并行。

### 2.1 收尾地图导出（`RtkFusion::exportMap` / `exportFrame`）

- 旧实现单线程，每个点都调一次 `correctionAt`（插值 + 指数映射），3.5 亿点。
- 现实现：每批 128 帧，OpenMP 并行变换（每线程独立 ifstream），按帧顺序拼块，前一块在后台线程写盘时变换下一批；同一帧内同一时间偏移（同一次发射）的点共用一个修正（缓存，结果与逐点计算相同）。RGB 地图：变换与打分并行，最佳颜色按帧顺序串行合并（与旧实现选择规则相同）。
- 结果：LIO（`wuhu_29_lio_9`）**89.5 s → 10.3 s**，345 块、352 573 611 点，与基线逐一相同（末块字节数相同）；LIVO（`wuhu_29_livo_11`，几何 + RGB 两份）**121.9 s → 32.7 s**。

### 2.2 收尾回环（`src/loop_closure.cpp`）

- 源子图只用点云，不再建 KD 树和法向（配准只用目标子图的树与法向）。
- 每个门限阶段（1.0 / 0.5 / 0.3 / 0.2 m）开始时，只保留“最近目标点在门限 + 0.25 m 内”的源点参与该阶段迭代；后续阶段在上一阶段的集合里再筛。初始 rms、信息矩阵与重叠度仍用全部源点计算（接受判据不变）。
- 结果：LIO 66.4 s → 58.2 s（92 对候选、接受 62 对；基线 91 / 59），LIVO 66.3 s → 58.5 s（92 / 68；基线 93 / 68）。点到面 rms 中位 0.049 → 0.041 m、修正中位 0.062 m，与基线（0.050 → 0.041、0.064）一致。剩余时间主要是目标子图法向估计与第一阶段全量最近邻，继续压缩需要改变配准近似，收益约 30 s / 整轮 18 min，未做。

### 2.3 评估（`scripts/evaluate_wuhu_round.sh`）

参考导出（`dump_bag_reference.py`）与轨迹评估都只读录制，改为并行，汇总前等待参考导出完成：LIO 204 s → 160 s，LIVO 222 s → 183 s。评估之后是轮次的关键路径（标准地图导出 69–89 s 与它并行）。

### 2.4 开 RViz 时的后端开销

开 RViz 后 `/rtk/map`（最近 30 帧的局部地图快照）每秒重建一次，原实现每个点调用一次 `correctionAt`，且每追加一帧都按精确大小重新分配整块快照（30 帧约 0.5 GB 内存拷贝）。改为同一时间偏移共用修正、容量按倍数增长（结果不变）。

| 20261013 前 290 s，后端每帧处理耗时 | 中位 | P95 | P99 | 累计 |
| --- | --- | --- | --- | --- |
| 不开 RViz（`mcp8_lio_full`） | 1.6 ms | 56.6 ms | 90.3 ms | 26.7 s |
| 开 RViz，原实现（`wuhu_29_lio_9`） | 1.3 ms | 497.0 ms | 563.2 ms | 119.6 s |
| 开 RViz，修正共用（`mcp12_lio_rviz300`） | 1.4 ms | 303.7 ms | 375.9 ms | 82.7 s |
| 开 RViz，再加容量倍增（`mcp12b_lio_rviz300`） | 1.4 ms | 215.5 ms | 267.1 ms | 64.2 s |

- 回放本身受实时约束（1 倍速）；停车段可用“长时间静止跳过”（仅 LIO）。

## 4. 控制台（Studio）

- 建图页新增“回环检测（收尾，需保存地图）”开关，默认开；关闭时传 `--set rtk.loop_closure_enabled=false`，并记入轮次参数。
- 轮次详情新增“回环”一行：候选对数、配准接受、RTK 约束剔除、最终保留、修正中位，以及未接受原因统计（来自 `loops.csv` / `loops_rtk_bound.csv`）；算法事件列表包含回环与收尾前释放前端地图的日志。
- 以 root 启动（`docker exec` 默认）时：先把 `results/` 与 `config/carlibration/` 下 root 所有的文件交还仓库属主，再降权为仓库属主运行，之后所有轮次、标定版本、导出和任务日志都归属主所有，宿主机上可直接删改。本次交还 2798 个文件，经 Studio 启动的 `wuhu_29_lio_9` 全部输出属主为 lhx。
- 修复：轮次已评估但 fusion 目录不存在（例如被精简）时，实时接口读取地图大小会抛异常。
