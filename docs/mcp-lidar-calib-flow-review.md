# MCP 专题：LiDAR 标定流程能否“一轮数据同时微调多个参数”（2026-10-21 凌晨）

日期：2026-10-21 凌晨 · 基线 `f332751`
数据：`/home/project/data/haibo/wuhu/29/20261013/ros2bag`；truck29-0930 的两次 LiDAR 流水线（10-19 16:53 / 17:25，手动窗口 0–180 s）

## 0. 结论

| 问题 | 结论 |
| --- | --- |
| 是否“一个阶段只标一个参数” | 不是。每个阶段都是一次数据多参数联合求解：后轴对齐 = 参考雷达 roll/pitch/yaw/x/y + LiDAR 时间偏移；静止地面 = 4 个雷达各自 roll/pitch/z；行驶段 = 3 个副雷达 6-DoF；RTK 轮次同时供 RTK 关联时间和后向雷达地面一致性两个阶段使用 |
| 为什么仍要分阶段、要两轮建图 | 数据依赖：后轴对齐、静止地面不需要建图（INS 位姿 / 静止帧）；行驶段精修需要用地面精修后的外参建一轮 LIO；RTK 关联时间和后向雷达地面一致性需要用行驶段精修后的外参再建一轮（RTK 时间不一致时再加一轮探测） |
| 两轮合并成一轮行不行（实测） | **不行，会损失精度。** 同一 180 s 窗口分别用地面版本、行驶段版本建图，后两个阶段的估计系统性不同：后向雷达 z +4.67 vs +3.73 cm、俯仰轴 +0.102 vs +0.126°；RTK 时间修正 +1.79 vs −1.59 ms。重跑行驶段版本的轮次与流水线原结果完全一致（−1.59 ms / +3.73 cm），说明差别不是随机波动 |
| 其他提速空间 | 都是阶段内部的纯计算，合计 ≤ 30–40 s（7 min 流水线的 5–8 %），例如行驶段精修里 25 s 的分时目标构建可以并行。按“不做低价值改动”的原则不改 |
| 结论 | 流程结构保持不变，不改代码 |

## 2. 合并实验

- 做法：用流水线原命令（`--rate 2.5 --duration 180 --quick-eval --no-map-chunks`）建两轮：`mcp34_lio_cg`（地面版本 v014_ground，即流水线第一轮）、`mcp35_lio_cd`（行驶段版本 v015_driven，即流水线第二轮）；在两轮上分别运行 RTK 关联时间估计和后向雷达地面一致性（父版本都用 v015_driven，后者会把存档按父版本外参重新投影）。
- 结果：

| 估计 | 地面版本轮次（合并方案） | 行驶段版本轮次（现流程） | 流水线原结果 |
| --- | --- | --- | --- |
| RTK 时间修正 | +1.79 ms（se 2.31） | −1.59 ms（se 1.48） | −1.6 ms（se 1.5） |
| 后向雷达 绕 x / 绕 y / z | +0.102° / −0.021° / +4.67 cm | +0.126° / −0.015° / +3.73 cm | +0.126° / −0.015° / +3.73 cm |
| 地面残差中位（前 → 后） | 2.29 → 1.19 cm | 1.77 → 1.10 cm | 1.77 → 1.09 cm |

- 原因：第一轮的 LIO 用的是行驶段精修前的副雷达外参（最大差 6 cm / 0.19°），前端位姿和地图都稍差；后两个阶段虽然会按新外参重新投影回波，位姿仍来自这一轮。
- 行驶段阶段本身可重复：在地面版本轮次上重跑，结果与 v015_driven 相差 ≤0.01° / 0.1 cm。

## 3. 没有采用的其他想法

- 用历史增益跳过 RTK 探测轮：各车实测增益 0.50–0.99（同一车 ±0.03），沿用上一次的增益误差约 0.5 ms，但结果会依赖之前的标定，违背“每次完整标定都从出厂版本开始、不依赖以前结果”的原则。
- 行驶段改用 INS 位姿、省掉第一轮 LIO：脚本里已有原始包重新去畸变的路径，实测与地图几何不一致（truck29raw v033 后雷达 +5 cm / 0.14°），不可行。
- 只在后端重放 RTK 探测（前端与 RTK 时间无关）：需要新增一套离线后端重放程序并保证与在线完全一致，工作量大、风险高，收益约 1 min（仅在需要探测时）。
