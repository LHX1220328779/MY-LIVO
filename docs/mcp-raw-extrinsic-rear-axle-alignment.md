## 1. 问题定位

- 35 个历史版本（v001…v035）的参考雷达外参 `transform_matrix_lidar_6` **逐位相同**，都是用户手调值 t=(−0.033, 7.793, 0.051) m、rpy=(1.300, −1.670, 90.160)°。ground（`refine_multi_lidar_extrinsics.py`）、driven（`refine_multi_lidar_yaw.py`）、SLAM 静态自检都以参考雷达为基准只修其余雷达。
- 厂家原始文件的参考雷达 t=(0.107, 7.613, 0.051)、rpy=(−1.002, −2.072, 88.957)，与手调相差 (+2.30, +0.38, +1.28)°、(−14, +18) cm。原流水线从它出发只会把其余雷达对齐到一个错的参考上。
- 旧 schema-5 文件里的 `rear_axle_coordinate_correction` 正是“手调参考雷达 × 原始参考雷达⁻¹”，被一次性乘到所有雷达上——即整机刚体修正；新阶段把这一步自动化。
- `import` 要求 `transforms.midrange_camera_to_rear_axle`，原始导出只有 `midrange_camera[0].tf_lidar_to_camera`（相机←前雷达），直接报错退出。

## 2. 方法（`scripts/refine_rear_axle_extrinsic.py`）

- 位姿：`imu_data/odometry`（`vehicle_rear_axle_rfu`，仅 `ins_pos_mode=4`，车速 ≥1 m/s、起步 5 s 后），时间约定与 SLAM 一致：点时刻 = 帧头 + `time_offsets.lidar` + 点内相对时间；位置取 +`rtk_position`（0.025 s），姿态取 +`ins_attitude`（0）。
- 前雷达每 2 帧取 1 帧、0.25 m 体素、3–80 m，逐点插值去畸变拼到世界系（120 s 录制约 550 帧、400 万点）。
- 目标函数：跨时刻点到面一致性。每个采样点与“时间差 >1.5 s 的回波”拟合的局部平面比较；点和平面都随外参移动（对称雅可比），因此解与初值无关；Huber、粗到细（半径 1.0→0.5 m、平面度 12→4 cm）。
- 未知量：整机修正（绕参考雷达位置的旋转 + 水平平移，车体系）+ LiDAR 时间偏移。z 不可观（整图平移），保留父版本。
- 修正 C 乘到**全部雷达和相机**：父版本的雷达间/相机-雷达相对标定保持不变（§5.3 的 E8 证明相机必须随整机转，否则原生尺度偏 1.4%）。
- 质量门：修正 >6° / >60 cm / >80 ms 或残差不降 → fail（不写版本，退出码 3）；未收敛或前后两半解不一致（>0.2°/20 cm/10 ms）→ warn。报告含前后半段复现性与各自由度信息量。
- `--dof`：rpy_xy（默认，原始出厂文件必须）/ rpy / xy（只应用对应部分；求解总是联合的——若把旋转固定在手调值再解平移，两半录制的杠杆臂相差 29/55 cm）。`livo_calib.py axle --dof auto` 按父版本的 `calibration_type` 自动选择。

### 5.3 灯柱指标的专项排查

- 现象：凡应用自动旋转（E4/E5/E7、原始外参全流程）的 LIVO 轮次，单灯柱（−10.75, −274）多期一致性中位 12.5–13.6 cm，手调旋转为 9.0 cm；LIO 下两者相当（8.96 vs 8.28–9.35）。
- 已排除：LiDAR 时间偏移（E1 仍 13.4）、横滚（E5 13.2）、偏航（E7 12.5）、平移（E6 更差 15.1）、相机偏航与时间（LIVO A 轮次在灯柱偏航修正前已是 13.6）、相机处理方式（E8 证明相机必须随整机转）。评估口径：柱段 45.5–48.5 m 含 z≈48 灯臂簇，换成 44.8–46.8 m 中位数后差距缩小约 1 cm（9.6 vs 11.7–11.8）。
- 分布而非幅度：灯柱轴线在 13 个分块上的总漂移两者相近（手调 24 cm、自动 25–31 cm），手调谱系在远距离接近段（0–17 s）更集中，自动谱系从起步就线性漂移。该段恰是单天线 INS 航向起步收敛期，INS 对齐的外参更“跟随” INS。
- 结论与取舍：对原始出厂文件只能用数据一致解（远优于原始 2.3° 误差，且其余全部指标达到或超过历史最优）；对已手调的父版本，默认 `--dof auto` 只应用杠杆臂 + 时间偏移（E9：灯柱不变，轨迹/地面/残差全面变好）。最终裁定旋转哪套更真实，需要一段往返录制（用户手调所用的那类数据）复核，§8 给出命令。

## 6. 标定逻辑复核（需求 2）

- 参考雷达→后轴：原体系的系统性缺口，已由 `axle` 补上；它只用录制本身的 INS/RTK，不依赖建图，是链路里最便宜的一步（≈1 min）。
- LiDAR 时间偏移：旧值 −0.125 s 来自“LIO 姿态滞后 INS”的回归；跨时刻一致性给出 −0.146 s，5 种设置离散 ≤5 ms，LIO（L2→L3）与 LIVO（E1 vs v009）均证实更优，因此由 `axle` 写入 `time_offsets.lidar`（`--keep-time-offset` 可保留旧值）。
- 杠杆臂：手调前向短 ≈23 cm；数据一致解应用后 LIO（L1→L2）、LIVO（E6→E5、E0→E9）均变好。
- 旋转：数据一致解与 INS 一致到 0.1°，但与原始 IMU 重力方向差 0.1–0.2°（后端失准角吸收），LIVO 单灯柱指标偏好手调旋转（§5.3），故对已对齐父版本默认保留旋转。
- 其余阶段：ground（静止判定）、driven（两遍 + 质量门）、camtime、灯柱偏航、俯仰闭环逻辑合理；从原始外参出发复现了手调谱系的雷达间相对外参（≤0.05°/2.6 cm）与相机闭环（闭环 pass，尺度 1.0001），无需改动。
- 效率：原始外参 → 可生产版本 ≈20 min（LiDAR 4 min + 相机标准 16 min）；日常微调仍可用快速闭环（≈4.5 min）。
- 局限：120 s 单程录制平移两半差 7–9 cm（6 min 含掉头时信息量 ×4）；z 不可观（沿用厂家值）；新车首标建议录制含一次掉头或往返的 2–6 min 数据。

## 8. 使用方法

```bash
cd /home/project/MY-LIVO; T=tools/calib/livo_calib.py; D=/home/project/data/haibo/wuhu_livo/ros2bag
/usr/bin/python3 $T import --source config/carlibration/wuhu/truck29/raw/perception_truck29.json --mine wuhu --truck truck29
/usr/bin/python3 $T axle --id wuhu/truck29/v0NN_import --bag $D          # --dof auto：原始文件解全部 5 个自由度 + 时间偏移
# 之后照常：ground → LIO 48 s → driven → 相机流水线（Studio 两条一键流水线）
/usr/bin/python3 $T axle --id wuhu/truck29/v032_camloop --bag $D         # 已精修父版本：只应用杠杆臂 + 时间偏移（保留旋转）
/usr/bin/python3 $T axle --id <版本> --bag <往返录制> --dof rpy_xy       # 用往返数据复核旋转（推荐新车首标时做一次）
```

Studio：LiDAR 标定流水线第一步即“后轴对齐”（原始导入与已精修父版本都可直接运行；请求体 `skip_axle: true` 跳过、`dof` 强制自由度）。
