# Vehicle body filtering, multi-LiDAR RViz diagnostic, and stationary IMU start

Update: 2026-10-27

## Body filter and calibration path

- Calibration-based body rectangles are applied to each LiDAR's raw sensor-frame points before the source-to-rear-axle parent transform is used for stitching. The Studio multi-scan samples every dataset LiDAR topic, transforms each with the selected parent calibration, and uses a stable source-specific color shared with the mapper regardless of bag metadata order; filtered points are shown separately.
- The automatic calibration pipeline copies the current vehicle's body-filter definition into the selected parent calibration before its data-assessment step and before any calibration stage. The UI lists versions of the selected vehicle, and the pipeline resolves the explicitly chosen parent by its calibration file; the legacy `from_factory` flag is ignored. Existing non-factory versions are therefore valid parents, subject to the normal file/stage validation.
- `tools/livo/effective_config.py` makes the selected calibration authoritative for `multi_lidar.body_filter.enabled`, `minimum_z`, and per-topic rectangles. It removes stale YAML rectangle overrides, including when the calibration explicitly disables filtering. The mapper logs, per source, filter state, rectangle count, z floor, and first-frame before/after point counts. Runtime filtering is in `multi_lidar_pcl_cbk`, before the calibrated point cloud is queued for mapping.

## RViz source-color stream

- The mapper publishes `/multi_lidar/filtered_colored` only when it has a subscriber. Each synchronized frame is already body-filtered and transformed by the parent calibration into the rear-axle frame; the visualization cloud preserves separate source RGB colors without changing intensity or the points used by estimation.
- `rviz_cfg/wuhu_truck29.rviz` enables this PointCloud2 display with the RGB8 transformer. The point cloud frame is `aft_mapped`, which the Wuhu RViz config already relates to fixed frame `mine` through mapper odometry/TF. Source order follows `multi_lidar/topics`; each topic's RGB mapping is logged at startup.
- The existing `/rtk/cloud_current` and map displays remain unchanged; the new display is an additional body-filtered diagnostic view. The mapper warns for any enabled source with no rectangles. The target Zongyang recording was checked numerically: its `front_lidar` produced no returns inside the coarse rear-axle body envelope in five time windows and in the first seven live C++ diagnostic frames, so its empty rectangle list was retained for this recording. This does not validate other vehicles or recordings, and the generic warning remains.
- The target bag exposed a repeatable front-left body-return cluster; a narrow vehicle-specific rectangle was added to the active Zongyang calibration and verified in the actual filtered C++ stream. See the real-recording results below; interactive RViz visual sign-off is still outstanding.

## Startup initialization assessment (no stationary runtime gate)

- Wuhu truck29 uses `imu_int_frame=200` and `sample_interval_sec=0.01`. Its 2.0 s stationary prefix plus 0.2 s assessment window gives a **2.2 s advisory threshold**, not a runtime requirement. The mapper proceeds with ordinary count-based initialization even when the recording starts in motion.
- `tools/livo/assess.py` checks gyro/acceleration statistics and, where configured, a rolling INS speed window; gravity convention and sensor transforms are applied for assessment. A short or moving startup prefix is reported as an advisory, and a later stop does not extend the initial contiguous-prefix metric. Runtime still validates finite/ordered timestamps, initializes after the configured sample count, and preserves the existing IMU gap handling (including fatal handling of an over-limit post-initialization gap).
- `initializeMineFrame()` selects available INS poses in its look-back window and may apply the configured INS speed filter; that is separate from stationary-prefix duration. `tools/livo/assess.py` schema 4 scans acceleration as well as gyro and evaluates only the initial contiguous stationary prefix. The duration item has `fix=advisory` and cannot by itself stop the default calibration pipeline.
- The target recording previously measured a 0.61 s continuous stationary prefix against the 2.20 s recommendation. That is an initialization-quality warning only; it does not establish that the subsequent map is accurate or inaccurate. The prior runtime rejection is retained below as historical behavior before the gate was removed.

- No RViz GUI/screenshot was inspected in this session. The actual filtered topic was captured and checked numerically, but the user's strict “no body points visible” criterion still needs an interactive RViz visual check, especially for low body/tyre returns and points outside the coarse envelope.
