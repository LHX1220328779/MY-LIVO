# huaining/truck08 后轴标定失败核查（2026-11-11）

## 范围与结论

原任务 `results/.studio/jobs/1a1c9b9ae3a.json`，2026-11-11 16:29:11 启动，16:32:02 在 axle 退出。输入是 `huaining/truck08/v001_import` 和 `/home/project/data/haibo/huaining/08/20261111/ros2bag`，全录制窗口、`rpy_xy`，并非仅使用前置运动分析选出的 48 秒。

确认三项原因：

1. 原结果的平移修正约 74.55 cm，超过 60 cm 门限；独立两半前向平移差 5.4 cm、时间差 13.2 ms，未达到原有大修正豁免的严格确认条件。退出码 3 是质量拒绝，不是程序崩溃。
2. 时间候选更改基准时，`shifted()` 更新了逐点 INS 位姿，却沿用原始时刻的速度、角速度。点位置和时间雅可比不在同一时刻，转弯时会把线性化误差混入时间与前向杆臂。原候选网格错误偏好 −90 ms 基准，最终偏移 −10.1 ms；修复后候选在 +150 ms 附近形成内部最小值，最终偏移 +6.7 ms。这里的基准/修正均相对父版本 −125 ms，最终偏移是绝对标定参数。
3. `9888c0d` 把质量失败退出移到报告写出之前；`livo_calib.py` 的清理又删除没有 calibration.json 的目录。原 stage.log 和拒绝报告因此丢失，错误只剩不存在的文件路径。旧任务被删除的日志不能当作已恢复；原算法复现证据单独保留。

数据支持相对已录制 INS 后轴位姿约 77 cm 的系统修正。没有独立测量，不能仅据此判定厂家外参的绝对物理误差，也不把 RTK 固定解等同于真值。

## 控制台门限与失败行为

标定页和失败的 LiDAR 流水线任务页均提供 8 项门限，按矿山/车辆保存。流水线、单步、失败续跑均传到同一求解入口，单位与记录一致。

| 参数 | 默认值 | 行为 |
| --- | ---: | --- |
| max_translation_cm | 100 cm | 拒绝上限；按本次用户要求由 60 cm 调高 |
| max_rotation_deg | 6° | 拒绝上限 |
| max_abs_time_ms | 250 ms | 最终时间偏移绝对值拒绝上限 |
| max_residual_increase_mm | 0.5 mm | 内部残差中位数允许增加量 |
| warn_time_change_ms | 80 ms | 相对父版本时间大幅变化警告 |
| warn_split_rotation_deg | .2° | 分半旋转差警告 |
| warn_split_translation_cm | 20 cm | 分半水平平移差警告 |
| warn_split_time_ms | 10 ms | 分半时间差警告 |

其余默认值沿用原值。拒绝上限不再被“短录制”或“大修正分半确认”自动绕过；分半确认照常计算和记录，需扩大范围时由用户明确调整。数值需有限、非负，非法输入在启动前给出对应字段错误。CLI 对应 `--max-translation-cm 100` 等选项，`--help` 可查全部选项。

失败先打印并写出完整报告，包含实际值、阈值、对应设置项。任务错误不再截断到 300 字符。失败目录保留 `stage.log`、`stage_report.txt` 和 `failed.json`；没有完成 meta 的中间 calibration.json 改名为 incomplete_calibration.json，防止被当作成功版本。版本编号包括失败尝试，后续重跑不会删除或覆盖旧证据。

续跑只复用已完成步骤，当前调整后的门限用于尚未完成的 axle 步骤。已完成的后轴阶段不会在之后的失败续跑中被悄悄重算，需要重标后轴时选择父版本重新启动。

浏览器已实际验证 8 个输入框、失败任务页显示、100→120→刷新保持→恢复100；未改其他车辆设置。服务在无运行中任务时重启以加载 jobs.py；刷新浏览器即可看到新界面。

真实数据拒绝验证：任务 `1a1c9d9f8fa` 特意使用 35–80 s 和旋转上限 0.1°，实测修正 0.937°，按配置拒绝。完整错误也保留了短窗口两半旋转差 0.714°、平移差 46.84 cm，不把拒绝误写成仅有一项问题。目录 `v004_axle` 保留日志/报告/failed.json，没有 calibration.json/meta.json；这是有意验证拒绝路径的诊断轮次，不是默认 6° 门限下的新故障。短窗口没有绕过硬上限；控制台默认旋转门限未被改成 0.1°。
