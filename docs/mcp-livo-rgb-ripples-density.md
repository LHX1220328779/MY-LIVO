## 1. 偏移：内参还是外参 / 时间

用多视角光度一致性（同一个 LiDAR 回波在 2–60 m 外的多个视角里应看到同样的纹理）把内参（fx/fy 比例、k1）、相机旋转、图像时间一起放开拟合，回波按 4 m 棋盘格分两半交叉验证：

- 旋转 + 时间：两半留出集的代价降低 26.5 % / 27.9 %，两半结果差 ≤ 0.01° / 1.1 ms；路线另外三段同样的修正降低 28.6–29.8 %。
- 再加内参：留出集只多 ≤ 0.9 %，fx −0.04…−0.2 %、fy +0.13…+0.6 %、k1 ≈ −0.006…−0.009，两半之间的差与改进同级。

所以“偏”来自外参旋转和时间，内参是准的。阶段与验证见 `docs/mcp-camera-photometric-calibration.md`；最终轮 mcp45 用的就是它写出的 `v043_camphoto`。

## 2. 视锥波纹

### 2.1 截图

- `results/.mcp/c/rf_R2.jpg`、`rf_703.jpg`：同一块路面，左 mcp33（旧规则，按行）、右 mcp45（新规则，3 cm 体素），2 cm/像素俯视，3×3 像素点。旧图上成串的 V / U 形台阶（相机视野的底边和两侧边）在新图上消失；`gf_703.jpg` 是同一块的 5 cm 全局彩色图，同样消失。
- `results/.mcp/c/vb33_703.jpg`：成因复现。四幅图依次是存储颜色、取色点的图像行号、图像列号、取色视角编号（每 4 个循环）。视角编号图是 2 m 一条、底边加两侧张开的带子，行号图在每条带里从 ~700 递增到 ~1000（底边），存储颜色的亮度台阶与带边界重合。

### 2.2 机理

离线复刻 `LIVMapper::colourScan`（`results/.mcp/c/colour_rules.py`，与 mcp38 存储颜色逐点比对，74–94 % 相差 ≤ 3 个灰度级、97–99 % ≤ 12）：

- 前视相机先在远处（画面中部）看到路面点，车往前开，点向画面底边 / 两侧移动，最后离开画面。“最新的能看到它的视角”就是它即将离开画面的那一帧，57 % 的取色点离图像边 < 150 px，行号中位 830 / 1080。
- 视角每 2 m 缓存一个，相邻视角负责的区域以各自的离开边界（底边在地面上是横线，两侧边是向外张开的斜线）为界，所以地面被切成 2 m 一条、形状像相机视野的带子。带子一侧取自新视角的边缘（暗角、运动模糊），另一侧取自旧视角里更靠内的位置，亮度不连续。
- 量化：同一条带内相邻点（2 cm 内的地面点对）色差 2.6–3.1 灰度级，跨带 13.9–14.7，**4.5–5.6 倍**。拟合的暗角在画面水平边缘约 −21 %，各视角曝光差 P10 / P90 约 ±13–18 %。

### 2.3 方案比较（两块路面，地面点对；比值越接近 1 越看不出带子）

| 规则 | 跨带 / 带内色差比 | 局部纹理 | 说明 |
| --- | --- | --- | --- |
| 旧：最新视角 | 4.49 / 5.55 | 0.0238 / 0.0244 | 现状 |
| 最新的、离边 ≥ 150 px 的视角 | 5.25 / 5.19（自身带边） | 0.0216 / 0.0227 | 带子只是挪位置 |
| 交接羽化 100 px | 2.12 / 2.46 | 0.0221 / 0.0232 | |
| **交接羽化 150 px（采用）** | **2.04 / 2.04** | **0.0205 / 0.0218** | 按绝对色差算纹理 −11 % / −7 % |
| 交接羽化 200 / 250 / 350 px | 1.91–1.55 | 0.0189–0.0156 | 更软，纹理损失 20–36 % |
| 旧规则 + 暗角 / 曝光修正 | 2.71 / 2.69 | 0.0234 / 0.0241 | 需每台相机标暗角、在线估曝光，复杂 |
| 羽化 150 + 暗角 / 曝光修正 | 1.43（R2 路段） | 0.0218 | 比单羽化再好一点，同样复杂 |

采用交接羽化 150 px（`publish.rgb_view_feather: 90`，在原 60 px 边距之外）：一处小改动，去掉台阶，细节损失小；路牌（S1 / S2）正视图上各规则看不出差别。暗角 / 曝光修正需要新的标定量和在线曝光估计，收益有限，不做。

### 2.4 实现

`LIVMapper::colourScan`：每个回波仍按最新优先遍历视角；视角权重 = clamp((离边距离 − 60) / 90, 0.001, 1)，取 min(权重, 1 − 已有权重) 累加，权重满 1 即停。距离字节仍记录能看到它的最新视角，颜色截取距离（60 m）和 `map_export` 的“最近视角优先”语义不变（试过记录权重最大的视角：主视角常比最新视角远 2 m，1.3 % 的行被 60 m 截掉）。约一半的回波第一个视角就权重满 1，着色耗时 1.9 ms/帧（mcp38 同为旧规则 1.8 ms，属机器负载波动）。

## 3. 点数与文件大小

### 3.1 原因

| 统计（mcp38 全程） | 数值 |
| --- | --- |
| `map_N` 写入行 | 1.49 亿（2.39 GB） |
| 其中停车帧（< 0.2 m/s，55 % 的帧，主要是 227–591 s 一次 6 min 停车） | 0.89 亿行（60 %） |
| `rgb_map_N` | 1.37 亿行（91.8 % 的几何行有颜色，2.19 GB） |
| 每块 3 cm 体素重复度：前 60 s（行驶）/ 停车段 | 1.22 倍 / 7.90 倍 |
| 用户旧轮次 wuhu_29_livo_11（距离优先关、只用当前帧图像着色） | `rgb_map_N` 0.44 GB |

彩色点云变大是 Task 7 回看着色的结果（着色率 3–60 % → 92 %），加上停车帧把同一批表面重复写了约 70 遍（5 cm 体素）。行驶路面本身不冗余（2 cm 体素平均 1.13 行）。

### 3.2 处理（只动彩色产品）

- 体素：每个分块的彩色行按 3 cm 体素合并，输出质心 + 平均颜色（约 70 ms / 百万行）。每个分块的彩色部分是单独的任务，最多 3 个同时跑，与几何文件写盘、下一批扫描的转换并行；任务按分块顺序写文件、更新停车体素表。
- 停车：导出时按帧顺序判断，帧相对上一个行驶帧的原生位姿移动 < `save_rgb_voxel` 且转动 < 1° 即为停车帧。含停车帧的分块在体素合并后，去掉停车以来已经写过的体素（有序数组归并，停车结束清空；6 min 停车约 220 万个体素键、18 MB），所以停车点每个 3 cm 体素只写一次，覆盖不丢。
- 参数 `rtk.save_rgb_voxel`（默认 0.03 m；0 = 每帧每行都写，即旧行为），`run_wuhu_round.sh --rgb-voxel M`，Studio 建图页“彩色点云体素”。
- `map_N`、`global_map.pcd`、`global_map_rgb.pcd`（5 cm 全局体素，由存档生成）的点数不受影响；`global_map_rgb` 用的是新的羽化颜色（同一块路面的台阶同样消失，见 `results/.mcp/c/gf_703.jpg`）。

为什么停车帧不能直接跳过：每帧扫描的采样位置都略有不同。停车 228–591 s 的 3631 帧彩色行在 5 cm 体素上的并集是 94 万个，单帧只占 1.4 %，每 0.5 / 1 / 2 / 5 s 取一帧分别只有 53.7 / 42.4 / 32.9 / 23.7 %（`results/.mcp/c/stop_cov.py`）。第一版“停车帧不写颜色”（中间轮 mcp40）把停车点 30 × 30 m 内几何 5 cm 体素的着色覆盖降到 66.4 %（按体素去重后 95.0 %，见 3.3），所以改成按体素去重。

## 6. 没有采用

- 最新的、离边 ≥ B px 的视角（等于加大边距）：带子只是往里挪，跨带色差比仍 4.4–5.3。
- 暗角 + 每视角曝光修正：需要新的相机标定量和在线曝光估计；单独用比羽化差（2.7 vs 2.0），叠加只再好一点。
- 停车帧不写颜色、或停车时每隔 T 秒取一帧：停车点着色覆盖分别只剩 66 % / 24–54 %（见 3.2）。
- 2 cm / 5 cm 体素：2 cm 几乎不减点（路面 1.13 行 / 体素）；5 cm 路牌点数降到 63 %。
- `map_N` 的停车帧（60 % 的行）也可以同样去重，可再省约 1.4 GB 和对应的写盘时间；用户确认强度点云合适，本次不改。
