# MCP 专题：彩色点云是否“异帧上色”；路牌颜色染到背后植被（2026-10-21 深夜）

日期：2026-10-21 · 基线 `a381024`
数据：`/home/project/data/haibo/wuhu/29/20261013/ros2bag`
轮次：`mcp51_livo_final`（上一版）、`mcp52_livo_occ`（本次）、`wuhu_29_livo_11`（最初版 362c75b）

## 0. 结论

| 问题 | 回答 |
| --- | --- |
| 现在是不是用别的帧的图像给某一帧的雷达点上色 | **是。** 每个回波取“能看到它的最新一帧图像”的颜色：自己这一帧的图像，或之前 80 m 内每 2 m 留下的一帧。地图里留下的是车经过时离得最近的回波（距离优先，精度最高），那时它们多在车旁边或后面，前视相机看不到：只有约 3 % 的保留回波在自己那一帧的图像里 |
| 最初版是不是同帧上色 | **是**，但它上色的是另一批点：每帧图像里能看到的回波，也就是车还在远处时测到的远处回波（位置偏 10–20 cm，灯杆更粗、路牌有重影），再每 3 cm 留离雷达最近的一次观测 |
| 改回同帧上色行不行 | 不行。对现在的高精度回波同帧上色只能给约 3 % 的点上色（比最初版稀疏一个数量级）；要恢复最初版的密度就得改用远处回波，几何精度下降。两者都不满足“不降精度”，放弃 |
| 路牌颜色染到背后植被 | **是异帧上色的遮挡判断漏了**：给植被点上色的那帧图像里路牌挡在它前面，而判断遮挡只用了那帧自己的激光扫描，抽稀后的扫描投到图像上 60–80 % 的 8 px 格子是空的，路牌没被记成遮挡物，植被点就取了路牌的像素 |
| 改进 | 遮挡判断再加最近 20 帧（2 s）激光里高出地面的回波：路牌、灯杆、树干成为完整的遮挡物。路牌“影子”减少约 7 成以上并在视图里基本消失；开阔路段上色点数不变，密植被处被前景挡住的点改为不上色（少约 7 %）；几何不变 |

## 1. 证据

- 路牌 (−251.6, 130.3)（正面“保护绿水青山”、背面“最盼的是…”）：彩色点云从路边看，路牌左侧植被上出现了一块完整的路牌图案（`results/.mcp/rc2/ps_c5.jpg`）。
- 这块“影子”位于路牌以南 7–8 m、以西 3 m 的植被上，是 755 s 往南开时、相距 19–27 m 的那帧图像上的颜色，取色位置在画面右侧（u 1650–1800，正是路牌），而那帧自己的激光扫描在这些 8 px 格子里 99.8 % 没有任何回波（`results/.mcp/c/colour_rules.py` 复刻，`gb_c5_blue.npy`）。
- 抽稀后的扫描很稀：755 s 那一帧 5.1 万个回波里只有 1.0 万落在相机画面内，8 px 格子有回波的只占 20–40 %（`results/.mcp/rc2/frame_cover.py`）。

## 2. 改进方案比较（复刻，路牌附近 18 × 24 m，统计“取色视角里被路牌挡住却取了色”的行）

| 遮挡判断 | 被路牌挡住仍取色的行 | 有颜色的行 |
| --- | --- | --- |
| 现状：只用这帧自己的扫描 | 18 468 | 100 % |
| 自己扫描的高处回波向四周扩 1 格 | 8 169 | 94.7 % |
| 扩 2 格 | 3 059 | 81.1 % |
| 支撑检查（3 × 3 格内要有同深度回波） | 13 304 | 86.2 % |
| 多视角颜色一致才取色 | 16 318–17 964 | 99.1–99.7 % |
| **最近 10 帧的高处回波** | 6 635 | 97.4 % |
| **最近 20 帧的高处回波（采用）** | 5 064 | 92.8 % |
| 最近 10 帧 + 扩 1 格 | 2 373 | 76.6 % |

- 多视角颜色一致检查无效：相邻两个视角（相隔 2 m）看到的都是同一块路牌，颜色一致。
- 扩格会把遮挡物轮廓放大，挡掉大量本来可见的点；多帧累积只是把遮挡物本身补全，代价最小。
- “高处”= 比所在 1 m 列最低回波高 0.3 m 以上：地面不会挡住地面，也避免远处地面（一个格子里深度跨度大）被误判。容差 max(1 m, 5 %)：叶子后 1 m 内的叶子不算遮挡（颜色相近，无害）。
- 开阔路段（703 s 路段）三种设置的有色行都是 100 %；少掉的点都在密植被里，是在每个视角里都被前面的叶子或路牌挡住的点，以前取的是前景的颜色，现在不上色。

## 3. 最终轮 mcp52（与 mcp51 对比，同一份标定 v044）

| 指标 | mcp51（只用自身扫描） | mcp52（加最近 20 帧高处回波） |
| --- | --- | --- |
| 彩色点云里的饱和色点（蓝 / 红 / 黄，主要是路牌颜色） | 2903 个，其中成片落在植被上的 5 处（每处 2–11 m 长，平面 RMS 10–19 cm） | 1084 个，剩下的都在路牌板面上（平面 RMS 1–3 cm） |
| 路牌 (−251.6, 130.3) 从路边看 | 路牌左侧植被上有一块完整的路牌图案 | 消失（`results/.mcp/rc2/ps2_c5.jpg`，另一块路牌 `ps2_c6.jpg`） |
| 有颜色的几何行 | 1.367 亿 / 1.491 亿（91.7 %） | 1.316 亿 / 1.491 亿（88.3 %） |
| `rgb_map_N` | 3730 万点，597 MB | 3492 万点，559 MB（路面 < 6 m：1170 → 1160 万点） |
| 着色耗时 | 1.9 ms/帧 | 2.9 ms/帧 |
| 优化轨迹 vs RTK | 0.95 / 3.62 / 7.61 cm | 0.97 / 3.58 / 7.00 cm，100 % ≤ 10 cm |
| 地面平面 RMS 中位 5–20 m / 20–40 m | 19.63 / 32.91 mm | 19.43 / 32.96 mm |
| 内存峰值 | 6101 MB | 6195 MB（遮挡缓存约 14 MB，其余为轮次波动） |

几何不变（精度指标在轮次波动内）。少掉的约 3.7 % 彩色行都在路边植被里：每个能看到它的视角里，它都被更近的叶子或路牌挡住，以前取的是前景（叶子 / 路牌）的颜色，现在不上色。mcp52 运行时机器上有远程桌面等程序占用（空闲时负载 10–12），LIO/VIO 每帧都慢了 4–7 ms，整轮用时 1174 s 不代表本改动的开销；着色本身多 1.0 ms/帧。


## 4. 改动

- `src/LIVMapper.cpp`、`include/LIVMapper.h`：`colourScan` 维护最近 `rgb_occluder_frames`（默认 20）帧的高处回波，生成每个视图的遮挡格（8 px，最近深度），取色时在原来的自身扫描检查之外再检查一次（max(1 m, 5 %)）。按帧并行投影。
- `config/wuhu_truck29.yaml`：`publish.rgb_occluder_frames: 20`（0 = 只用自身扫描，与以前一致）。
